# Device frames

Apple Watch Series 11, Apple Watch Ultra 3 and iPhone 17 Pro Max use the original transparent PNG bezels from [Apple Design Resources](https://developer.apple.com/design/resources/). The PNGs in `official/` are copied byte for byte from Apple's downloadable packs. Series 11 uses the dark Slate Milanese Loop. The artwork retains its original colours, bands, reflections and canvas; the gallery displays it without added shadows or rotation.

## Screenshot placement

The shared component places screenshots underneath the original Apple artwork. `official/geometry.json` records the image dimensions, the transparent display bounds and a clip path measured from the PNG's alpha channel. It also records each original filename and SHA-256 checksum. The SVG defines only the screenshot clip; the hardware is entirely Apple's PNG.

Android uses the original Pixel 10 artwork from [Android Studio's device-art resources](https://android.googlesource.com/platform/tools/adt/idea/+/refs/heads/mirror-goog-studio-main/artwork/resources/device-art-resources/pixel_10/). Its 1080 × 2424 display starts at (59, 55), matching the bundled `layout` file. The original WebP is copied unchanged.

The Google Pixel selector includes six original frames from that collection: Pixel 10, Pixel 10 Pro, Pixel 10 Pro XL, Pixel 10a, and Pixel 10 Pro Fold with its display folded or unfolded. The original `back.webp`, `mask.webp` and `layout` files are retained in `official/google/`. `official/google-catalogue.json` records the source URLs, SHA-256 checksums and measured display geometry. The screen clips use the enclosed transparent display in each bitmap, so they account for differences between the actual artwork dimensions and the emulator's nominal layout dimensions. These are the models available in the public collection checked on 14 October 2026; they are not Pixel 11 artwork.

Wear OS uses the Pixel Watch SVG illustration, with its screenshot bounds taken from `screen-shape`. It is an illustration rather than official Google device artwork. All renderers use one coordinate system for the screenshot and frame, so resizing cannot shift the screenshot relative to the bezel.

```tsx
import { DeviceFrame } from '../DeviceFrame.tsx';

<DeviceFrame device="ios" src="/screens/iphone.png" alt="Bibless on iPhone" />
<DeviceFrame device="watchos" src="/screens/apple-watch.png" alt="Bibless on Apple Watch" />
<DeviceFrame device="watchos-ultra" src="/screens/apple-watch-ultra.png" alt="Bibless on Apple Watch Ultra 3" />
<DeviceFrame device="android" src="/screens/phone/barcode.png" contentOnly alt="Bibless on Android" />
<DeviceFrame device="wearos" src="/screens/watch/qr.png" alt="Bibless on Pixel Watch" />
```

Screenshots keep their aspect ratio and fit within the opening. `contentOnly` adds the missing system bars to Android `SiteScreenshotTest` captures; omit it for screenshots that already include those bars. Omit `src` to inspect a frame's transparent opening. Each instance namespaces its clip IDs so repeated frames can share a page.

## Landing page

The shared hero shows Android with the Pixel Watch illustration alongside iPhone 17 Pro Max between Series 11 and Ultra 3, both with dark Milanese Loops. Both platform previews appear below one headline and the Android and TestFlight beta links, with no platform toggle. The previews sit side by side on desktop and stack on mobile. All devices are tilted as complete SVGs, so screenshots stay registered with their frames. The original artwork files remain unchanged. Existing `#apple` links open the shared hero.

The Apple screens in `../screens/` are plain native app captures with demo data, bundled with the web app so they also work in builds without Xcode. `iphone-qr.png` comes from the existing iPhone screenshot test, run against an isolated iPhone 17 Pro Max simulator; `apple-watch-qr.png` is copied unchanged from the existing Ultra 3 QR capture. Refresh these from the corresponding native screenshot tests when the app UI changes. Android and Wear OS screens continue to be generated by `SiteScreenshotTest` in CI.

## Local gallery

Start the web app and open `/src/landing/frames/preview.html`. The development gallery previews all five device families and accepts a screenshot per frame. The official cards link to the manufacturer's original resources; the Pixel Watch illustration offers a standalone SVG download.

The Apple style selectors include every PNG variant in the three downloaded packs: 44 Series 11 frames, 13 Ultra 3 frames and 30 iPhone frames (87 total). They cover case sizes, materials, colours, bands, and portrait or landscape orientation. The Google Pixel selector includes six phone frames. Switching a style keeps the uploaded screenshot and fits it to that variant's display opening. The unfolded Pixel Pro Fold fits the full card width.

All original PNGs are extracted to `official/apple/`, grouped by device and band or phone model. `official/apple-catalogue.json` records each file's original name, source pack, SHA-256 checksum and display geometry. Every extracted PNG matches its source byte for byte.

Pass an optional `variant` ID from `deviceVariants[device]` to `DeviceFrame` to use a specific style. `defaultDeviceVariants` identifies the current defaults, including the Series 11 dark Milanese Loop. Imported asset URLs load each bitmap when that variant is displayed.

```tsx
<DeviceFrame device="android" variant="google/pixel_10_pro" src="/screens/phone/barcode.png" alt="Bibless on Pixel 10 Pro" />
<DeviceFrame device="android" variant="google/pixel_10_pro_fold/default" src="/screens/phone/barcode.png" alt="Bibless on an unfolded Pixel 10 Pro Fold" />
```

## Apple artwork terms and source

Apple owns the official PNGs. They are subject to the bundled [Apple Design Resources License](./official/Apple-Design-Resources-License.rtf) and Apple's [Marketing Resources and Identity Guidelines](https://developer.apple.com/app-store/marketing/guidelines/), rather than the project's own code licence. Use the artwork for depictions of the app on the Apple platforms it supports. The gallery links to Apple for the original resources instead of offering standalone Apple artwork downloads.

## Google artwork terms and source

The Pixel phone artwork comes from Android Studio's device-art collection, whose source metadata is licensed under Apache 2.0 by the Android Open Source Project. The original layouts and masks, the source `device-art.xml` and a copy of the Apache licence accompany the artwork. Google image bytes are preserved unchanged.

Google's device-art generator permits framed previews on websites and promotional materials. Keep Google Play listing screenshots unframed, as stated on the [generator page](https://developer.android.com/distribute/marketing-tools/device-art-generator).
